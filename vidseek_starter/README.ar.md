# VidSeek — البحث الدلالي في الفيديو لوكلاء الذكاء الاصطناعي

**VidSeek** مكتبة Python تجريبية صُممت للعمل محلياً وتعتمد على نموذج `google/embeddinggemma-2` من Google. تتيح للتطبيق فهرسة ملفات الفيديو المحلية واسترجاع المقاطع المناسبة انطلاقاً من استعلامات باللغة الطبيعية. تتضمن النتائج مسارات الملفات والطوابع الزمنية والبيانات الوصفية ودرجة التشابه الجيبي، مما يسمح لوكيل الذكاء الاصطناعي بتحديد المقاطع التي ينبغي فحصها أو فتحها.

> VidSeek مشروع مستقل وتجريبي، وليس منتجاً رسمياً من Google.

## ما الذي تفعله المكتبة وما الذي لا تفعله؟

- تحوّل النصوص ومقاطع الفيديو إلى تضمينات متجهية دلالية قابلة للمقارنة باستخدام EmbeddingGemma 2.
- تقسّم الفيديوهات إلى مقاطع ذات طوابع زمنية قبل الفهرسة، بحيث يمكن تحديد الفترات الزمنية ذات الصلة.
- تخزّن التضمينات والبيانات الوصفية في قاعدة بيانات SQLite محلية.
- توفّر واجهة Python ومخططات أدوات قابلة للتحويل إلى JSON لاستخدامها مع وكلاء الذكاء الاصطناعي.
- تعمل محلياً بعد تنزيل الاعتماديات وأوزان النموذج، ولا تحتاج إلى واجهة API خارجية لاستضافة التضمينات.

التضمينات **ليست** نصوصاً مفرّغة من الصوت أو ترجمات أو أوصافاً تفصيلية أو ملخصات مولّدة. تهدف النسخة الأولية إلى استرجاع المقاطع المناسبة. إذا احتاج وكيلك إلى الكلمات المنطوقة حرفياً أو تفسير المشاهد أو أوصاف كاملة لها، فيمكنك دمج المكتبة مع نظام لتحويل الكلام إلى نص مثل Whisper و/أو نموذج توليدي متعدد الوسائط.

## المتطلبات

- Python الإصدار 3.10 أو أحدث.
- تثبيت FFmpeg وإتاحة الأمرين `ffmpeg` و`ffprobe` ضمن متغير البيئة `PATH` عند استخدام التقسيم ذي الطوابع الزمنية.
- توفر ذاكرة RAM/VRAM كافية لإعداد النموذج المختار. تُنزّل أوزان النموذج عند أول استخدام.
- يُحمَّل النموذج من خلال Sentence Transformers وTransformers. يدعم EmbeddingGemma 2 النوعين `bfloat16` و`float32`، ولا تفرض هذه المكتبة استخدام `float16`.

## تجربة سريعة

```python
from vidseek import VideoEncoder, VideoIndex

encoder = VideoEncoder(device="cpu")  # استخدم device="cuda" على جهاز NVIDIA متوافق
index = VideoIndex("./vidseek.sqlite3", encoder=encoder)

# ينشئ تضميناً منفصلاً لكل مقطع مدته 20 ثانية.
index.add_video(
    "./my_video.mp4",
    segment_seconds=20,
    metadata={"title": "My video", "project": "demo"},
)

results = index.search("كلب يركض في حقل مغطى بالثلج", top_k=5)

for result in results:
    print(result["video_path"])
    print(result["start_seconds"], result["end_seconds"])
    print(result["score"], result["metadata"])
```

لإنشاء تضمين واحد للفيديو كاملاً، استخدم `index.add_video("./my_video.mp4", segment_seconds=None)`. في هذه الحالة، إذا تعذّر تحديد مدة الفيديو، فقد لا توفّر النتائج طوابع زمنية مفيدة لتحديد مشاهد بعينها.

## استخدام VidSeek كأداة لوكلاء الذكاء الاصطناعي

```python
from vidseek import VideoAgentTools, VideoIndex

index = VideoIndex("./vidseek.sqlite3")

# افتراضياً، يمكن للوكيل البحث،
# لكنه لا يستطيع فهرسة مسارات عشوائية في نظام الملفات.
tools = VideoAgentTools(index)

# استخدم هذه المخططات عند تسجيل الأدوات في إطار عمل متوافق.
schemas = tools.tool_schemas()

# للسماح للوكيل بفهرسة الملفات،
# حدّد مجلد وسائط مسموحاً به صراحةً:
# tools = VideoAgentTools(index, allowed_roots=["./approved_media"])
# schemas = tools.tool_schemas()  # سيشمل الآن index_video

# نفّذ استدعاء الأداة الذي أعاده إطار عمل الوكيل.
result = tools.execute(
    "search_videos",
    {"query": "شخص يفتح باب سيارة حمراء", "top_k": 3},
)
print(result)
```

الوظائف المتاحة:

- `search_videos(query, top_k=5)` — البحث الدلالي وإرجاع مقاطع الفيديو المرتبة حسب الصلة.
- `index_video(video_path, segment_seconds=20, title=None)` — فهرسة ملف محلي سمح المستخدم بالوصول إليه.

**ملاحظة أمنية عند دمج المكتبة مع الوكلاء:** تكون الفهرسة التي يبدأها الوكيل معطّلة ما لم يتم إعداد `allowed_roots` صراحةً. ولا يمكن فهرسة إلا الملفات الموجودة داخل المجلدات المسموح بها. ينبغي للتطبيقات المخصصة للاستخدام الإنتاجي أيضاً فرض قيود على أحجام الملفات ومدتها وترميزها.

## كيف يعمل تقسيم الفيديو؟

يستخدم الإعداد الافتراضي `segment_seconds=20` برنامج FFmpeg لإنشاء مقاطع فيديو مؤقتة، ثم يحسب تضميناً لكل مقطع ويسجّل وقت البداية والنهاية. تُحذف المقاطع المؤقتة بعد الفهرسة، بينما تبقى التضمينات والبيانات الوصفية في SQLite. عند إعادة فهرسة مسار موجود، لا تُستبدل السجلات السابقة إلا بعد نجاح حساب جميع التضمينات الجديدة.

يأخذ EmbeddingGemma 2 عينات من إطارات كل مقطع؛ ولا يحلّل كل إطار بمعدل الإطارات الأصلي الكامل. يمكنك تعديل `VideoEncoder(fps=..., max_frames=...)` لتحقيق توازن بين السرعة والتغطية البصرية. قد تحسّن المقاطع الأقصر دقة تحديد الزمن، لكنها تزيد مدة الفهرسة وحجم قاعدة البيانات.

## القيود الحالية

- تنفيذ تجريبي في مرحلة Alpha؛ لا يوجد إصدار منشور على PyPI حتى الآن.
- يدعم ملفات الفيديو المحلية فقط؛ ولا تقبل `VideoIndex.add_video` روابط URL أو تدفقات فيديو مباشرة.
- يفحص البحث فهرس SQLite خطياً. بالنسبة إلى المجموعات الكبيرة، يمكن إضافة فهرس متجهات مثل FAISS أو sqlite-vec أو Qdrant أو أي نظام تخزين متجهات مناسب آخر.
- لا تتضمن النسخة الحالية تفريغ الكلام إلى نص أو فصل المتحدثين أو OCR أو تتبّع الأجسام أو التلخيص أو الاستدلال البصري التوليدي.
- تعتمد الجودة والأداء الفعليان على إصدار النموذج والجهاز ومحتوى الفيديو وطول المقاطع وإعدادات أخذ العينات.
